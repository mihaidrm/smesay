# 0016 Chapters: grouped items per screen, with free navigation, 2026-10-01

Decided by Mihai in the Claude Code cloud session of 2026-10-01.

1. The respondent sees one chapter per screen: the AI's area grouping, with every item of the
   area as a compact card that holds its own answer controls. One item per screen stays as an
   option the PM picks when building the instrument, not the default. The product's strength is
   condensing the list into a fast journey.

2. A chapter row sits at the top of every screen: About you, the areas, Wrap up. The respondent
   moves between them freely. About you holds the respondent fields; Wrap up holds the missing
   item field, the closing question, the review, confidence and sign-off. Continue is never
   blocked; the Wrap up lists what is still missing and Submit waits for it.

3. On the respondent side the PM's accent colour marks the selected answer, the active chapter
   and the progress bar. Buttons stay ink so every instrument stays readable whatever the accent
   (Brand 06). The prototype has the accent as a tweak, default Marlow Group's #1F4F7A.

Replaces item 2 of design note 03 (one item per screen on the phone) and amends the E5 layout
templates in stories/backlog.md: chapters (default), one item per screen, single long page.

Consequence: respondent boards rebuilt (note 12); docs/design-system.md updated; the PM app
builder lists chapters first.
