# Design note 51: rating items on the live link, 2026-10-04

Made in the Claude Code cloud session of 2026-10-04 for stories/E7-2, under decision 0044.

## What was decided

- One card component for the Build preview and the live link. The live link controls the
  card's draft (the pick, the reason, the comment) from the page; the preview keeps its own
  and saves nothing. A note on the live card reads Not rated yet, Say why., Write your
  question., or Saved; the preview shows the picked label once complete.
- The card's slot holds one box. An answer that needs a reason (another value than the
  proposal, Not needed, Unclear) shows the reason box with the story's prompt; an answer
  that does not shows "+ comment", which opens the comment box. The draft keeps both texts
  while the respondent switches answers; the server stores the reason only when it is
  needed and the comment only when it is not, so a stored answer never carries both.
- The server decides the stored kind and value from the pick, the instrument's method and
  the item's proposal (classify); the client's word for the kind is never taken.
- Saving: each card's change waits 400 ms for the next one, then a PUT per item; focus
  leaving any control or the page being hidden sends whatever waits at once, with keepalive
  when the page is hidden. One request per card is in flight at a time; a newer change
  waits for it, except when the page is hidden, which cannot wait (docs/review-list.md).
  A request with no answer in 10 seconds is given up, so the newer change goes out. The server locks the response row for each write, so a card's changes are
  stored in the order they were made. Saved shows when the server answered the newest
  request sent for the card and nothing newer waits. A closed or revoked link reloads the page onto its state; a response this
  device lost (cookie cleared) returns to About you with a sentence, every card marked not
  saved, and Start sends the cards again.
- The card frame is 260 px. With a box in the slot it may grow, so the box keeps two lines
  (52 px) under a two-line title and a two-line prompt; the footer grows when the server's
  sentence wraps.
- One item per screen moves inside a chapter with Previous item and Next item; moving to the
  next chapter is E7-4's Continue. The single long page is one screen: every area as a
  heading over its cards; Back returns to About you.
- The incomplete answer is stored too (a Change with no reason yet), so a reload shows the
  pick; it does not count as answered.
