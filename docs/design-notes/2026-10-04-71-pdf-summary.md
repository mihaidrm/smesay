# Design note 71: the PDF summary, 2026-10-04

Made in the Claude Code cloud session of 2026-10-04 for stories/E10-3, under decision 0044.

## What was decided

- The PDF is HTML printed by Chromium (Playwright's Page.pdf), so the fonts, the status colours
  and the tables are the app's own; one browser per summary, closed after.
- Page 1: the workspace and the project, the strip's tiles as the PM chose them, the agreement
  by area as stacked bars, and the confidence histogram. Then the items of each area, the
  registers, and on its own page the sign-off record and the actions.
- Every bar has its counts in words under it and as its accessible name, so nothing rests on
  colour; the PDF is tagged.
- The sample's band and the page numbers are Page.pdf's header and footer templates, which
  print on every page. A position: fixed band printed on all pages but the last in a test
  render, so it was dropped.
- The page limit is 30. Over it the file still downloads and the Export tab says how long it
  runs; the route sends the count in x-summary-pages.
- The export log keeps the summary's page count as its rows.
- Rated takes the missing-item blue that starts the values ramp, apart from Unclear's violet;
  Not answered is the surface with a dashed strong hairline; the histogram's empty bins are a
  4 px hairline, and the average is printed under it.
- At most two summaries render at once per process, each stops after 60 seconds; the page runs
  no script and loads nothing but data: URLs. The document title is fixed ("Summary"), so the
  page counter never reads a typed name.
- Hosting: the server needs Chromium at run time (PLAYWRIGHT_CHROMIUM_PATH, else Playwright's
  own download). This is a launch-gate item for the hosting plan (docs/review-list.md).

## Components added

- The Summary for the deck card on the Export tab, with the page note in the sun tint under
  the button (ExportDownload gains a pages prop). No new design-system component.
