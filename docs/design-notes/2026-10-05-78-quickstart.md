# Design note 78: the quickstart, 2026-10-05

Made in the Claude Code cloud session of 2026-10-05 for stories/E12-2, under decision 0044.

## What was decided

- One page, /app/quickstart, inside the app shell: the workspace name above the title, the
  intro, the four steps as numbered cards in two columns (Import, Shape, Build, Share, the
  stepper's order), "Then: read the results" in a tinted card, then Start a project as the
  primary button and Open the sample project as a text link. Desktop only, as the PM side in R1
  (decision 0020). No new component: cards, the button and the link come from the design
  system.
- "Four steps, one screen each" in the copy file is read as four cards on one page; the copy
  file now says so. A stepped walkthrough would be an in-product tour, which the story keeps out
  of R1 (E15 owns tips).
- The gate is the column, not the redirect: Projects (/app) sends a member whose
  quickstart_seen_at is null to the quickstart, and the quickstart page stamps it on first
  load. Naming a workspace still redirects to /app, which then sends to the quickstart. This
  covers an invited member too, once per workspace, as the story's "per person per workspace"
  says. A deep link (an invite to a project, a bookmark) is not redirected.
- Migration 0027 sets quickstart_seen_at to created_at on every membership that exists when it
  runs, so nobody already using the app is sent to the quickstart after the deploy.
- The page stamps after its project list has loaded: a failed load shows the error page and
  does not count as seen.
- The stamp is a conditional update (where quickstart_seen_at is null) that reports whether it
  was the first, so E13-1's quickstart_seen event can be written once.
- Help is a sidebar footer link with the lucide CircleHelp icon, above the mode toggle.
- The sample link is left out when the workspace has no live sample: Results of a deleted
  sample is a 404 and an archived one is out of the list.

## Why

The story asks that the column stops the page showing again; a redirect on workspace creation
alone would show it once to the owner and never to a member.
