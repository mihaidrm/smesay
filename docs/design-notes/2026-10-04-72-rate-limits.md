# Design note 72: rate limits, 2026-10-04

Made in the Claude Code cloud session of 2026-10-04 for stories/E11-1, under decision 0044.

## What was decided

- The counts live in the process's memory (src/lib/ratelimit.ts), as the passcode attempts of
  E6-1 do: the app runs as one instance from `docker compose up`, and a count in memory costs no
  database write per request. More than one instance needs a shared table; the launch gate
  carries it.
- Respondent routes and the logo route: a fixed window of 60 seconds, 100 requests per address,
  counted in src/proxy.ts before the app renders. The 429 page is plain HTML with the design
  tokens, light and dark, since nothing of the app has rendered yet.
- Sign-in: 5 attempts per email and per address in 15 minutes, then a wait of one minute that
  doubles while the attempts go on, back to one minute after a quiet day. A magic link request is
  an attempt; a provider callback is one when it fails. The wait is shown in minutes.
- The address is the first X-Forwarded-For entry. A request without one is not limited by
  address: a shared "local" bucket would let one visitor lock out every visitor of a deploy
  without a proxy. The host's proxy must set the header and drop what a client sent.
- Each store holds at most 50,000 keys; expired keys go first, then the oldest.

## Components added

- None. The 429 page is a string in src/lib/ratelimit-copy.ts.
