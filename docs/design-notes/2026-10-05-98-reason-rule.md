# Design note 98: when a reason is required, 2026-10-05

Made in the Claude Code cloud session of 2026-10-05, under decision 0044. Mihai: "When setting
up these things, the PM should be able to say when its mandatory to add comment or not".

## What was decided

- The Scoring card on Build gets "When a reason is required", three radio cards after the
  labels, drawn like the method's cards: When the answer differs (the default), Never, On every
  answer. It sits with the method because it changes what an answer is, and it locks with the
  method once the instrument is published: a rule changed mid-run would turn answers already
  given complete or incomplete after the fact. The locked line names both: "Published
  instruments keep their method and when a reason is required. Build a new instrument to
  change them."
- When the answer differs is the rule the product had before this note (design note 12,
  stories/E7-2): a value other than the proposal (change), Not needed (disagree) and Unclear
  need their reason or question; agree and pick need nothing. Every existing instrument takes
  it (migration 0035, default `differs`), and so do the visitors' sample and the Build
  preview of a project with no instrument yet.
- Never keeps the boxes on the card with their prompts. An empty reason or question leaves the
  card complete, so the note reads "Saved" and the Wrap up does not list it.
- On every answer also asks an agreeing answer and a rating (`pick`, the proposal hidden or
  absent) for text. That text is the comment, where agree and pick already keep it: no new
  column, and Results, the registers, the CSV and the item detail read it where they always
  did. The card opens the comment box on its own for those answers, labels it "Comment,
  required" and drops the "+ comment" toggle; the card has no note until it is written (design note 99), and the Wrap up lists it as "Reason not written yet".
  The prompts of the reason boxes stay as they are.
- Unclear's question follows the same rule as the reasons: required under When the answer
  differs and On every answer, optional under Never. A separate switch for Unclear was not
  added; three cards cover the request, and a fourth combination would need a second control.
- Text in the box the kind does not use never completes an answer (a reason typed on an
  agreeing answer is dropped by the server, as before; answerFor keeps the reason only for
  change, disagree and unclear).

chapter-screen.tsx and respondent-app.tsx pass the rule. Board: PmApp draws the three cards.
