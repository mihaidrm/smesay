# Design note 69: the CSV exports, 2026-10-04

Made in the Claude Code cloud session of 2026-10-04 for stories/E10-1, under decision 0044.
The PM app board's Export tab and design note 40 (every export takes the page's filter) are
the starting point.

## What was decided

- Four CSV files: Answers, Items with totals, People and Missing items, one card each, as
  E8-1's audit asked; the JSON and PDF exports come with E10-2 and E10-3.
- Each file is the page's view: the same filter and the same include-unsubmitted switch, read
  from the query string as the page reads it. A file is built from the very queries the page
  shows, so the reconciliation test adds the rows up to the page's numbers.
- Before the header: the watermark line on the sample, the filter in words when one is on,
  and a line saying whether answers not submitted are included.
- A value is written as the scale's code with the instrument's label in the next column (two
  columns: value and label), so a file sorts by code and reads by label.
- Every field is quoted, lines end in CRLF, the file starts with the BOM, dates are ISO 8601
  with "+00:00" spelled out.
- The download is a link to a route under /api/projects/[id]/export/[file]; the file name is
  the project's name, the file and the date. The route streams the rows in chunks of 500
  lines from a table built in memory (at most 2,000 items and the answers of 500 people, so
  well inside memory); every download writes an export_log row.
