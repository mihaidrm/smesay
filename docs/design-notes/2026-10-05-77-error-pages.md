# Design note 77: error pages, maintenance and session expiry, 2026-10-05

Made in the Claude Code cloud session of 2026-10-05 for stories/E11-6, under decision 0044.

## What was decided

- The 404 and 500 pages use the auth frame with the lockup, the same as sign-in: the root
  not-found.tsx, a root error.tsx for pages outside /app and the links, /app's error.tsx, and a
  global-error.tsx with its own html and body for an error in the root layout. One component
  (src/components/app/server-error.tsx) holds the 500 page.
- A respondent link has its own 404 in the respondent frame: notFound() under /r/[token] and
  any address below a link ([...rest]). Its 500 is the existing error.tsx of the link (E6-1).
- The support address is NEXT_PUBLIC_SUPPORT_EMAIL, because the 500 pages are client
  components; the placeholder is hello@smesay.app, shown as text until the domain is bought.
- Maintenance is a switch in the proxy: MAINTENANCE=1 answers every request with 503 and
  Retry-After, a page for a page request and JSON for the respondent app's calls, which keep
  the answers and retry. The link's state check ignores 503 like 429, so the page stays.
- Session expiry: a save that finds no session answers "signed out" instead of sending the page
  to sign-in. The form keeps its text, shows the banner with a sign-in link that opens in a new
  tab, and keeps a draft in the tab's session storage (src/components/app/use-draft.ts) that a
  reload brings back. The banner's copy leaves out the hours: the app cannot know them.
- The rule against "invalid input" is a copy-scan rule for src/ only; docs and stories quote it.

## Audit

The fresh-context audit found 1 blocking point: with no session cookie, the proxy redirected a
server action to sign-in before it ran, so Next's client got a reply it could not read and the
page fell to the 500 page. The proxy now lets a server action under /app through; every action
checks the session itself. Also fixed: the draft is written only after a save answered "signed
out", so "What you typed before you were signed out is back" is never shown otherwise, and a
draft is cleared only when the saved text is what is on screen; "It has been logged." shows only
for errors the server raised (they carry a digest); the respondent's Start shows the
maintenance line on 503; the banner keeps the page's query; global-error's comment says it is
always light; SECURITY.md names the draft storage; .env.example says NEXT_PUBLIC_SUPPORT_EMAIL is
fixed at build time.
