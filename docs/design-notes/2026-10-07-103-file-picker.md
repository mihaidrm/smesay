# 103 The file picker is a button, 2026-10-07

Mihai, 2026-10-07, with a screenshot of Settings, Brand, the Logo field showing the browser's
bare "Choose File  No file chosen": "its impossible to know that choose file is a button looking
at it - this happens with multiple things in the app where you have to choose a file to upload.
Rework this".

Why it looked like that: the three file fields were plain `<input type="file">` elements and
the browser drew its own control. Chrome draws "Choose File" as a grey rectangle beside "No file
chosen"; the app's buttons are pills. Only the project import had a `file:` style on the
browser's button, and it was still not the secondary button.

Checked everywhere per decision 0056: `grep 'type="file"' src` finds three, Settings (the
workspace logo), Import (the list's upload card) and Import a project (the .json file). The
workspace export is a download, not an upload; the respondent side and the landing page take no
file. No canvas board draws a file field.

Decided:
- One shared component, src/components/app/file-picker.tsx: a label styled with the secondary
  button's classes (buttonVariants({ variant: "secondary" }) from src/components/ui/button.tsx,
  so it is the same pill as every other secondary button, in both modes, tokens only) around
  the real file input. The input stays in the DOM with its id, name, accept and the field's own
  Label, off screen with sr-only, so the keyboard, screen readers and Playwright's setInputFiles
  work as before; a click on the label opens the file dialog
  (html.spec.whatwg.org/multipage/forms.html#the-label-element, activation behaviour).
- The chosen file's name shows beside the button at 14 px in muted text; before a pick the same
  line says "No file chosen" (the browser's own words, kept so nothing new has to be learnt).
  When the form resets after a successful save (react.dev/reference/react-dom/components/form)
  the name clears with it.
- Keyboard: the focus stays on the input; the 2 px violet ring with its 2 px offset shows on
  the label while the input has focus-visible (has-[:focus-visible], as the About you radio
  cards). Disabled while the form is busy: the same control at 40 percent, as every button.
  The hand cursor on the label (design note 101 gives it to the browser's own button; the
  label gets cursor-pointer itself).
- The button's words are a verb: "Choose a file" by default, "Choose an image" for the logo.
  The words live in FILE_PICKER_COPY beside the component and in docs/copy/app.md, one row per
  screen with a picker.
- The input keeps its field Label and gains the button's label, so its accessible name reads
  "Logo Choose an image". Kept rather than hiding the verb from screen readers; a row in
  docs/review-list.md.

Where: docs/design-system.md, Components, one line. The styleguide (/styleguide, Components)
shows the picker at rest and disabled. Test: src/components/app/file-picker.test.tsx (the verb,
the hidden input with its attributes, the hint, the disabled flag). The e2e specs that upload
(e2e/import.spec.ts, e2e/settings.spec.ts, e2e/project-transfer.spec.ts, e2e/export-summary.spec.ts,
e2e/respondent-a11y.spec.ts) find the input by its field label as before, unchanged.
