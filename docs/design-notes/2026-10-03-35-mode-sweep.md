# Design note 35: the mode sweep, 2026-10-03

Mihai, after the design v2 merge: "improve the animation that happens when switching from
dark mode to light mode. It should be a gradual change top left corner to bottom right
corner, like pulling a blanket folding it over, and it should be like 1 to 2 seconds long."

## What was built

- The toggle (src/components/app/mode-toggle.tsx) wraps the class flip in
  document.startViewTransition, the View Transition API
  (developer.mozilla.org/docs/Web/API/Document/startViewTransition; Baseline since
  October 2025 per that page). The browser snapshots the page before and after the flip
  and animates between the two snapshots.
- The animation (src/app/globals.css, mode-sweep): the old snapshot keeps still (its
  default fade is removed) and the new snapshot wears a mask three times the page in size,
  a 135 degree gradient opaque for 44 percent, soft over 12 percent, then transparent. The
  mask moves from its transparent end to its opaque end over 1,400 ms with an ease in and
  out, so a soft diagonal edge travels from the top left corner to the bottom right and the
  new mode appears behind it, like a blanket pulled across. The edge is soft rather than a
  hard fold, which reads better over text.
- Scoped to an html class the toggle sets for the duration, so no other view transition
  inherits the mask.
- Off under prefers-reduced-motion (the toggle then flips at once) and in a browser without
  startViewTransition (same). No other behaviour changes; the stored choice and the script
  before paint are as in design note 34.

## Checks

Typecheck, lint, the styleguide Playwright test (the toggle still flips, persists and
follows the system setting; in Chromium the flip happens inside the transition's update
callback, so the assertions see the class at once). The motion itself is checked by eye in
the browser; a test of the mask's position would test the browser, not the product.
