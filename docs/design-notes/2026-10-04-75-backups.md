# Design note 75: backups and restore, 2026-10-04

Made in the Claude Code cloud session of 2026-10-04 for stories/E11-4, under decision 0044.

## What was decided

- A backup is a folder named by its UTC time, so backups sort and never overwrite: the database
  in pg_dump's custom format (compressed, restorable selectively), every bucket object under
  objects/, a listing, and a manifest with every table's row count, which the restore compares.
- pg_dump and pg_restore come from the PATH, the compose service or the postgres:16-alpine
  image, so Mihai installs nothing and CI matches the database's version.
- Restore only into an empty database, after the name is typed: it never overwrites data. It
  runs in one transaction. Objects go back only into an empty bucket, so a restore beside the
  live app cannot bring back deleted files.
- At the launch gate the folder becomes an S3 prefix in another bucket, written with the app's
  S3 settings; the nightly run is a cron line on the host, written in the runbook.

## Components added

- None (command-line only).

## Checks

- src/lib/backup.test.ts; the restore drill in docs/runbooks/backup-restore.md; CI's
  `npm run backup:check`.

## Audit

The fresh-context audit found 3 blocking points: the connection string, password included, went
to pg_dump and pg_restore on the command line and could come back in an error; a restore beside
the live app put back objects deleted since the backup; acceptance 3 (the restore on Mihai's PC)
was marked met. Now the connection goes in libpq's variables and errors are redacted, objects go
back only into an empty bucket and each is checked, and the story says acceptance 3 waits on
Mihai. Also fixed: one transaction for pg_restore, the full error's last five lines, restore from
an s3:// prefix, every S3 setting read before the database is touched, a probe object restored into a new empty bucket in CI, every object's size checked,
SECURITY.md listing these scripts, the temporary backup deleted and backup files private, the
emptiness check covering sequences, indexes and types and the migration log counted, a bucket
name that is not valid refused, and the prompt no longer showing the name to type.
