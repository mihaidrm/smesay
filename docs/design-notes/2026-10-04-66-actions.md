# Design note 66: Write actions with citations, 2026-10-04

Made in the Claude Code cloud session of 2026-10-04 for stories/E9-1, under decision 0044.
The PM app board's Actions tab and decision 0033 (two citation lists) are the starting point;
this note records what was decided while building it.

## What was decided

- The model never sees a database id, and never a respondent's name or email from the
  fields. Every item, respondent, answer and missing item gets a short ref (I1, R1, A1, M1); a
  respondent is shown only by the answers to the instrument's dropdown fields (role, team),
  the name field left out even when the PM made it a dropdown. The reasons, questions and
  missing items go as typed, so a name a respondent wrote in them reaches the model; the
  prompt asks for no names in the why, and nothing checks it. The app maps the refs back; an action citing a ref it was not given, or citing
  nothing, is dropped before it is stored.
- Only the answers that carry words go to the model: a different priority, not needed and
  unclear, with their reason or question, plus the missing items. Agreement is in the item's
  counts. Only submitted responses are read (decision 0030), whatever the page's switch says.
- Four kinds, each with a pill: Rewrite, Groups disagree (conflict), Follow up, Coverage. The
  kind is a column (insight.kind), null for rows written before it.
- A run replaces the open actions and keeps done and dismissed ones (E9-2 adds the controls).
  A run that keeps no action leaves the open ones as they are. Two runs at once write one
  after the other (the project row's lock).
- An action whose every citation is gone (a missing item cleared since) is not shown and not
  counted in the tab's number.
  The new actions are stamped a millisecond apart so the tab lists them in the model's order.
- The run's tokens and cost are shared over the actions it kept, the rest on the first, so a
  run's actions add up to its ai_run row.
- A citation names the people as Results does (the name field, else the invite's name or
  email, else Anonymous [N]) and groups them by item: "Ana and Bo on CL-02". An item with no
  reference (a pasted list) is named by its text in quotes, cut at 40 characters.
- The refusals have their own words for this tab: the shaping ones say "the list is imported",
  which means nothing on Results. Each says the answers are still on the other tabs.
- The sample shows its seeded actions read-only; writeActions refuses it too.
- The eval set is two invented response sets with the kinds a good run writes; a spec passes
  when every expected kind is kept and no action was dropped.

## Components added

- ActionsTab and WriteActions (results/actions-tab.tsx, write-actions.tsx). The action card is
  the card class with NeutralPill for the kind; no new design-system component.
