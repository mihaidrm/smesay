# Design note 22: the paste box, 2026-10-02

Story E3-4. The PM app board has no paste control (its Import step shows a file), so the box
is composed from the design system here, inside the E3-2 upload card. Screenshot beside the
boards: import-paste-desktop.png (the box open with six lines, and the preview below it).

## The box

Under the file input, a tertiary link "Paste a list instead". It opens a textarea (six rows,
mono 13 px so the bars line up) labelled "Paste a list", with the one-line rule under it in
muted 13 px ("One item per line. Add an area and a proposed value with a bar: text | area |
value.") and the primary "Use this list" pill on the right. The error of the last attempt
("Paste at least two lines, one item per line.") sits under the rule in the danger colour with
role alert and the id paste-error.

## The preview of a pasted list

The same preview card as a file: the summary line reads "Pasted list, [N] items.", there are
no sheet or header row pickers, and the three columns are A Item, B Area, C Proposed value,
so the mapping card guesses Item text, Area and Proposed value by itself.

## Decisions taken here

- A pasted list is stored as the text the PM pasted (text/plain, under uploads/<workspace>/),
  so the import log (E3-6) can show it as "Pasted list".
- Leading numbers, bullets and dashes are stripped per line, bar-separated area and value
  are read, everything else is item text (stories/E3-4, acceptance 1 and 3).
